###     ПР2. Ответы на контрольные вопросы

#   1. Почему для хранения денег используют decimal, а не double? Что может пойти не так с double?

При работе с double, даже у простых десятичных дробей как 0.1 накапливается небольшая погрешность. При обычных расчетах это не страшно, но
при работе с деньгами это может доставить неприятностей. У decimal, разумеется, такой проблемы нет

#   2. Что произойдёт, если целочисленный тип (например, byte) переполнится — то есть значение выйдет за границы диапазона?

Если значение byte выйдет за границы диапазона, например, 255+1, то значение обнулится. Если же 0-1, то значение станет 255

#   3. Чем var отличается от динамической типизации в Python? В какой момент компилятор определяет тип переменной, объявленной через var?

В Python можно сменить тип, а в c# нельзя. Компилятор определяет тип переменной в момент компиляции.

#   4. Какой тип данных всегда возвращает Console.ReadLine(), независимо от того, что ввёл пользователь?

string - строку

#   5. Чем int.Parse отличается от int.TryParse в поведении при некорректном вводе (например, буквы вместо цифр)?

Если в int.Parse засунуть буквы, то он выдаст ошибку и все. А int.TryParse продолжит работу

#   6. Что означает false, возвращённый из int.TryParse, и что при этом попадёт в переменную, переданную через out?

false, возвращённый из int.TryParse, означает что перевод в целое число не удался, а в переменную, переданную через out скорее всего попадет 0.

#   7. Приведите пример, когда стоит использовать TryParse, а не Parse — и объясните, почему.

TryParse стоит использовать в принципе везде, где присутствует пользовательский ввод. Неизвестно что захочет ввести пользователь, и будет лучше если
код не завершит работу после не того ввода. TryParse предохраняет от подобных ситуаций.
